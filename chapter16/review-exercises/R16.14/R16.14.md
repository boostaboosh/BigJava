R16.14
In the implementation of the LinkedList class of the standard Java library, the
problem described in Exercise •• R16.10 and Exercise ••• R16.12 results in a
ConcurrentModification Exception. Describe how the LinkedList class and the iterator
classes can discover that a list was modified through multiple sources. Hint: Count
mutating operations. Where are the counts stored? Where are they updated? Where
are they checked?

Where are the counts stored?
The linked list class can contain a counter instance variable which is incremented every time the list is mutated. 
The linked list iterator class can contain a mutation counter variable too. 

Where are they updated?
When addFirst, addLast, removeFirst, or removeLast are called on the linked list its mutation counter is incremented.
When the iterator is initialised its mutation counter is set to the same value as the mutation counter in the list 
the iterator is associated with.
When an iterator method which mutates the linked list is invoked on the iterator, e.g. add, set, or remove, the
linked list counter and the iterator counter are updated to the same value. It is easier to set the iterator counter to 
the same value as the linked list counter at the end of these methods than the alternative. Which is to check if a first
or last node was added or removed, and only then increment the iterator counter to match the linked list counter.

Where are they checked?
In the iterator before the execution of any mutator method, e.g. next, previous, add, set, or remove. 
The iterator checks that the linked list mutations counter matches its own mutation counter. 
If it doesn't that means the linked list was mutated outside of this iterator by invoking a mutator method on the 
linked list or by using another iterator. In which case a concurrent modification exception is thrown.
